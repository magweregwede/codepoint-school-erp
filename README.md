# SchoolERP — Greenfields High School (Demo)

A working demo of a High School Enterprise Resource Planning system, built to the
SRS in `SchoolERP_SRS_v1.0.docx`. **All data is mock** and is regenerated by the
seed script. The original SRS specifies Django + PostgreSQL + Redis + Celery; this
demo is a Next.js + Prisma + SQLite substitute that fits a single Vercel
deployment.

## Modules in scope

Eight modules built with full depth (admissions, transport, hostel, health,
documents, and parent/student portals are out of scope for this build):

| Module | Sections |
|---|---|
| **Finance** | Fees + AR, Suppliers + AP (PO/GRN/voucher), Cash & Bank, General Ledger |
| **HR** | Employees, Attendance, Leave, Payroll |
| **Academics** | Students, Attendance, Marks, Reports, Timetable |
| **Library** | Catalogue/OPAC, Loans (short + long term), Fines |
| **Inventory** | Assets, Movements, Vehicles, Consumables |
| **Communications** | Compose (SMS/Email/in-app), Message log |
| **Reports & Dashboards** | Role-tailored dashboards, canned reports, charts |
| **System Admin & Audit** | Users & roles, append-only hash-chained audit log, configuration |

## Running locally

Prerequisites:
- Node.js 20 LTS or later
- A Postgres database. The free tier of [Neon](https://neon.tech) is the
  fastest path — sign up, create a project, and copy the connection string
  it gives you. The same connection string is used for local dev and Vercel.

```bash
# 1. Install deps (also runs `prisma generate` via postinstall)
npm install

# 2. Configure environment
cp .env.example .env.local
# Edit .env.local and paste your Neon DATABASE_URL.
# Generate AUTH_SECRET with: openssl rand -base64 32

# 3. Create tables in Neon
npm run db:migrate

# 4. Seed mock data: 12 users, 60 employees, ~600 students, 200 books,
#    150 assets, fee invoices + receipts, payroll runs, library loans,
#    asset movements, audit log
npm run db:seed

# 5. Start the dev server
npm run dev
# Open http://localhost:3000
```

To reset and re-seed at any time:

```bash
npm run db:reset && npm run db:seed
```

## Notes on RBAC

Permissions are codes of the form `<module>.<verb>_<object>`
(e.g. `finance.create_receipt`, `academics.approve_marks`). Roles bundle
permissions; the *System Administrator* role has the wildcard `*`.

The sidebar in `src/components/AppShell.tsx` only shows modules the user can
access. Each module layout calls `requireAnyPermission([...])` server-side, so
direct URL access is also blocked for unauthorised users (302 → `/forbidden`).

## Deploying to Vercel

The project ships with a `vercel-build` script that runs `prisma migrate
deploy && next build`. So a Vercel deploy will:

1. Apply the migrations to the Postgres in `DATABASE_URL`
2. Build the Next.js app

The seed step is **not** included in `vercel-build` (otherwise every deploy
would wipe the database). After the first deploy, run `npm run db:seed` once
locally with the production `DATABASE_URL` to populate the demo data:

```bash
vercel env pull .env.production --environment production
DATABASE_URL=$(grep DATABASE_URL .env.production | cut -d= -f2- | tr -d '"') npm run db:seed
```

Steps:

1. Create a Postgres database on [Neon](https://neon.tech) (free tier is fine).
   Copy the connection string.
2. `vercel deploy` (the CLI walks you through linking).
3. In the Vercel project settings → **Environment Variables**, add:
   - `DATABASE_URL` — your Neon connection string
   - `AUTH_SECRET` — `openssl rand -base64 32`
4. `vercel deploy --prod` to push to production.

The seed script is idempotent (it deletes everything and re-creates) so don't
re-run it accidentally on a populated production DB. After the first deploy,
remove the `tsx prisma/seed.ts &&` segment from `vercel-build` if you want
data to persist between deploys.
